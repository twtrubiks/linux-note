# Linux DNS 設定 — 用 NetworkManager (nmcli) 修改 DNS server

想把 DNS 換成 `1.1.1.1` 或 `8.8.8.8`，很多人第一個想到的是直接改 `/etc/resolv.conf`，

結果過一陣子 (重開機、換 Wi-Fi、DHCP 更新) 就被蓋回去了 :sweat_smile:

本篇實測環境：Debian 13，NetworkManager 1.52。

## 觀念

```
連線設定檔（每個 Wi-Fi / 有線網路各一份）
/etc/NetworkManager/system-connections/<連線名稱>.nmconnection
        │
        ▼
NetworkManager（再加上 DHCP 發的 DNS）
        │  自動產生
        ▼
/etc/resolv.conf   ← 程式要查 DNS 時讀這個檔案
```

**1. `/etc/resolv.conf` 是結果，不是設定來源**

官方手冊 `man NetworkManager.conf` 寫到 NetworkManager 會

*"update /etc/resolv.conf to reflect the nameservers provided by currently active connections."*

所以直接改它一定會被蓋掉，要改的是上游的連線設定。

**2. DNS 是綁在「連線」上，不是綁在電腦上**

改了家裡 Wi-Fi 的 DNS，換到公司的 Wi-Fi 是不會生效的。想讓所有網路都生效，請用 [全域設定](#所有網路都用同一組-dns全域設定)。

GNOME / KDE 圖形化介面改的也是同一份連線設定，可參考 [KDE 修改 DNS server](https://github.com/twtrubiks/linux-note/tree/master/kde-settings#kde-修改-dns-server)。

**3. 先確認你的系統是哪一種**

```cmd
ls -l /etc/resolv.conf
```

| 看到的結果 | 代表 | 確認 DNS 的方式 |
|---|---|---|
| 一般檔案，第一行 `# Generated by NetworkManager` | NetworkManager 直接管理（Debian） | `cat /etc/resolv.conf` |
| 連結到 `/run/systemd/resolve/stub-resolv.conf` | systemd-resolved（例如 Ubuntu） | `resolvectl status` |

systemd-resolved 的系統，`/etc/resolv.conf` 裡只會看到本機 DNS 中繼 `127.0.0.53`，

所以 Ubuntu 上 [nslookup](https://github.com/twtrubiks/linux-note#nslookup) 看到的 `Server` 是 `127.0.0.53`，不是真正的 DNS server。

兩種系統**修改的指令都一樣**，差別只在確認的方式。

## 修改單一連線的 DNS

```cmd
# 1. 查連線名稱 (NAME) 和網卡名稱 (DEVICE)
nmcli connection show --active

# 2. 修改 DNS，並忽略 DHCP 發的 DNS
nmcli con mod MYWIFI ipv4.dns "1.1.1.1 8.8.8.8" ipv4.ignore-auto-dns yes

# 3. 套用（con mod 只改設定檔，不會馬上生效）
nmcli con up MYWIFI
```

權限不足的話前面加 `sudo`。

`ipv4.ignore-auto-dns yes` 一定要加，不然 DHCP 發的 DNS 還是會被使用。

確認有沒有生效

```cmd
❯ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 1.1.1.1
nameserver 8.8.8.8
```

還原成 DHCP 自動取得

```cmd
nmcli con mod MYWIFI ipv4.dns "" ipv4.ignore-auto-dns no
nmcli con up MYWIFI
```

如果網路有發 IPv6 的 DNS，也要一起擋掉 `nmcli con mod MYWIFI ipv6.ignore-auto-dns yes`。

## 所有網路都用同一組 DNS（全域設定）

新增 `/etc/NetworkManager/conf.d/global-dns.conf`

```ini
[global-dns-domain-*]
servers=1.1.1.1,8.8.8.8
```

`*` 代表所有網域，依照 `man NetworkManager.conf` 的說明，全域設定會

*"override the ones from active connections."*

重新載入設定（沒生效就改用 `restart`），要移除時把檔案刪掉再 reload 即可。

```cmd
sudo systemctl reload NetworkManager
```

:warning: 全域設定會**連 VPN 推過來的 DNS 一起蓋掉**，如果公司 VPN 需要用內部 DNS 解析內網，改用單一連線設定比較適合。

## /etc/hosts 會比 DNS 先查

查詢的順序由 `/etc/nsswitch.conf` 決定

```cmd
❯ grep hosts /etc/nsswitch.conf
hosts:          files mdns4_minimal [NOTFOUND=return] dns mymachines
```

`files` (也就是 `/etc/hosts`) 排在 `dns` 前面，所以 `/etc/hosts` 有寫的網域就不會去問 DNS，

設定方式可參考 [設定 /etc/hosts](https://github.com/twtrubiks/linux-note#設定-etchosts)。

## 改了沒生效？

- 忘記 `nmcli con up` 套用設定。
- 改到的不是使用中的連線，用 `nmcli connection show --active` 確認。
- 沒加 `ipv4.ignore-auto-dns yes`，或是 IPv6 的 DNS 還在。

其他 nmcli 用法可參考 [nmcli 指令 - 連線到隱藏 Wi-Fi SSID 方法](https://github.com/twtrubiks/linux-note#nmcli-指令---連線到隱藏-wi-fi-ssid-方法)。

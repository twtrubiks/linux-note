# Linux DNS Settings — Change the DNS server with NetworkManager (nmcli)

When you want to switch DNS to `1.1.1.1` or `8.8.8.8`, the first thing many people think of is editing `/etc/resolv.conf` directly,

only to find it overwritten after a while (reboot, switching Wi-Fi, DHCP renewal) :sweat_smile:

Test environment for this article: Debian 13, NetworkManager 1.52.

## Concepts

```
Connection profile (one per Wi-Fi / wired network)
/etc/NetworkManager/system-connections/<connection name>.nmconnection
        │
        ▼
NetworkManager (plus the DNS provided by DHCP)
        │  auto-generated
        ▼
/etc/resolv.conf   ← programs read this file when resolving DNS
```

**1. `/etc/resolv.conf` is the result, not the source of the settings**

The official manual `man NetworkManager.conf` says NetworkManager will

*"update /etc/resolv.conf to reflect the nameservers provided by currently active connections."*

So editing it directly will always get overwritten; what you need to change is the upstream connection profile.

**2. DNS is bound to the "connection", not to the computer**

If you change the DNS of your home Wi-Fi, it won't take effect when you switch to your office Wi-Fi. To apply it to all networks, use the [global setting](#use-the-same-dns-for-all-networks-global-setting).

The GNOME / KDE GUI also edits the same connection profile, see [KDE change DNS server](https://github.com/twtrubiks/linux-note/tree/master/kde-settings#kde-修改-dns-server) (Chinese).

**3. First check which kind of system you have**

```cmd
ls -l /etc/resolv.conf
```

| What you see | Meaning | How to check DNS |
|---|---|---|
| A regular file, first line is `# Generated by NetworkManager` | Managed directly by NetworkManager (Debian) | `cat /etc/resolv.conf` |
| A link to `/run/systemd/resolve/stub-resolv.conf` | systemd-resolved (e.g. Ubuntu) | `resolvectl status` |

On systems with systemd-resolved, `/etc/resolv.conf` only shows the local DNS stub `127.0.0.53`,

which is why the `Server` shown by [nslookup](https://github.com/twtrubiks/linux-note/blob/master/README_en.md#nslookup) on Ubuntu is `127.0.0.53`, not the real DNS server.

**The commands to change DNS are the same** on both kinds of systems, only the way to verify differs.

## Change the DNS of a single connection

```cmd
# 1. Find the connection name (NAME) and the device name (DEVICE)
nmcli connection show --active

# 2. Change the DNS, and ignore the DNS provided by DHCP
nmcli con mod MYWIFI ipv4.dns "1.1.1.1 8.8.8.8" ipv4.ignore-auto-dns yes

# 3. Apply it (con mod only edits the profile, it doesn't take effect immediately)
nmcli con up MYWIFI
```

Add `sudo` in front if you don't have enough permissions.

`ipv4.ignore-auto-dns yes` is a must, otherwise the DNS provided by DHCP will still be used.

Check whether it took effect

```cmd
❯ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 1.1.1.1
nameserver 8.8.8.8
```

Restore to getting DNS automatically from DHCP

```cmd
nmcli con mod MYWIFI ipv4.dns "" ipv4.ignore-auto-dns no
nmcli con up MYWIFI
```

If your network also provides IPv6 DNS, block it as well with `nmcli con mod MYWIFI ipv6.ignore-auto-dns yes`.

## Use the same DNS for all networks (global setting)

Create `/etc/NetworkManager/conf.d/global-dns.conf`

```ini
[global-dns-domain-*]
servers=1.1.1.1,8.8.8.8
```

`*` means all domains. According to `man NetworkManager.conf`, the global setting will

*"override the ones from active connections."*

Reload the configuration (use `restart` if it doesn't take effect). To remove it, just delete the file and reload.

```cmd
sudo systemctl reload NetworkManager
```

:warning: The global setting **also overrides the DNS pushed by your VPN**. If your company VPN needs internal DNS to resolve the intranet, the single-connection setting is a better fit.

## /etc/hosts is checked before DNS

The lookup order is decided by `/etc/nsswitch.conf`

```cmd
❯ grep hosts /etc/nsswitch.conf
hosts:          files mdns4_minimal [NOTFOUND=return] dns mymachines
```

`files` (that is, `/etc/hosts`) comes before `dns`, so domains listed in `/etc/hosts` won't be sent to DNS.

For how to set it up, see [Set `/etc/hosts`](https://github.com/twtrubiks/linux-note/blob/master/README_en.md#set-etchosts).

## Changed it but it didn't take effect?

- Forgot to apply the settings with `nmcli con up`.
- Changed a connection that isn't the active one, check with `nmcli connection show --active`.
- Didn't add `ipv4.ignore-auto-dns yes`, or the IPv6 DNS is still there.

For other nmcli usage, see [nmcli command - Connect to a hidden Wi-Fi SSID](https://github.com/twtrubiks/linux-note/blob/master/README_en.md#nmcli-command---connect-to-a-hidden-wi-fi-ssid).
